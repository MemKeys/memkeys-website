## The four waypoints

1. **Emit.** An agent produces a *raw* fact and sends it with the one anchor key
   it already knows — a run id, a thread id. It never computes keys, validity
   windows, or embeddings itself.

2. **Key & append.** The server enriches the keys, applies temporal validity,
   and appends the fact to the **single keyed core**. Nothing is overwritten: a
   new version carries a `supersedes` link to the one it replaces, so the
   superseded value stays queryable (the dimmed card in the figure).

3. **Derive.** Graph and vector views are projected from the keyed core —
   **asynchronously and rebuildably**. They are never a second source of truth;
   losing one costs a replay, not data.

4. **Retrieve.** Agents read back three ways, all returning the authoritative
   record from the keyed core:
   - **Fetch** by the keys you know (exact, deterministic).
   - **Search** semantically *within a scope* — the keys bound the candidate set
     before similarity runs (the `scope: project:…` halo in the figure).
   - **Traverse** the graph to discover how entities connect.

## The four-op contract

| Operation | What it does | Waypoint |
|---|---|---|
| **Store** | write a fact, keyed | emit → key & append |
| **Fetch** | retrieve by the keys you know | retrieve |
| **Search** | semantic recall, within a scope | retrieve |
| **Traverse** | hop the graph from a start node | retrieve |

Store once, keyed. Graph and vector are views on the same facts — not three
copies to keep in sync.
